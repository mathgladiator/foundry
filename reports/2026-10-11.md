# 2026-10-11 - progress

The second day, and the first with systems: the foundry went from fixed assets to a full runtime pipeline. A tree pipeline of four systems now grows 28 species across ages and seasons, sways in the wind, and falls when felled. It runs in WebAssembly in the foundry and natively, byte for byte the same, behind a generated C API, and a stress tool measures it at forest scale. Fixed assets learned to break. Everything from today is uncommitted and in draft, waiting for the human's validation. The only commit dated today is `81b50fe` (00:08), which closed out 2026-10-10.

## The day in brief

1. **Design, before the build.** The design was rounded out with `ORG.md` (the source tree and its dependency rules), and a key rule: systems are hidden behind a macro-level C API, and no system escapes the runtime. `CLAUDE.md` took the settled decisions from the 2026-10-10 report.
2. **The tree pipeline.** Four systems (`tree_rig`, `tree_mesh`, `tree_colorize`, `tree_animate`) and the channels between them, first with 10 species, 4 ages, and 4 seasons, then 18, 22, and 28 species. They run in Wasmtime in the foundry, and every stage is checked byte for byte against its native build.
3. **The flattened runtime and the C API.** These were brought forward because the stress tool needs them. `tools/gen_pipelines.py` generates each pipeline's native code, and `runtime.h` is assembled from fragments, with a generated fragment per pipeline. The runtime has instances, a cache keyed by build parameters, update on a thread pool, and an instanced, skinned renderer.
4. **The stress tool.** A generic platform in `src/tools/stress/` with a generated `stress_$pipeline.c`, JSON plans, four phases, committed reports, and `--window` to fly through the forest.
5. **Seeing a pipeline.** The viewport gained a **Flow** tab and a **Video** tab:
   - The Flow tab shows how parameters reach each stage, what each stage's cache key is, and a probe of which dependencies actually change an output.
   - The Video tab exports a QA video (H.264 through `ffmpeg`) of every variation, behind a "Foundry QA" title slide.
6. **Books.** Every pipeline now has a book, and `book/tree_v1.md` is the first. Its numbers come from runs.
7. **Fracture.** Fixed assets can break. A fixed asset's LOD1 is cut by one of five algorithms, and the break is baked into a draft fracture item.
8. **Config tables, and a host free of trees.** Genomes moved out of the host into a generic config table compiled into the runtime. The host names no pipeline, system, or channel.
9. **Reference photos.** 66 public-domain and CC0 photos of all 28 species are in `demo/reference/trees/`, each with a provenance sidecar. Each genome links to its photos, which can be shown in the viewport's corner. The species were compared with them and retuned.

## Decisions made today

| Decision | Choice |
|---|---|
| Hidden systems | The game's C API exposes pipelines, their parameters, and macro-level configuration only; never a system, a system version, or a channel type (`ORG.md`, `design/api.md`). |
| Channel naming | `$family_v$version_$feature` (`tree_v1_rig`). The schema gives `family`, `version`, and `feature`, and the generator derives the rest. Systems keep `$name_v$version` (`design/flow.md`, "Naming"). |
| Pipeline data | Data such as species lives in config tables (`config/$table/`), edited by a generic, table-configured editor. It is compiled into the native runtime and hidden from the game, which sees only entry names. |
| Systems as isolated verticals | The host never names a pipeline, system, or channel. Drawable channels follow a convention (`positions`, `indices`, `matrices`, ...) rather than a type. |
| Interactions | An interaction such as a tree breaking is an `event`: a clock that stays negative until the game starts it, with a generated trigger (`foundry_tree_v1_start_break`). |
| Performance timeline | Every stress run writes a committed report to `perf/`, for draft and final pipelines alike, so regressions show as the renderer changes. |
| QA video | H.264 MP4 through the system's `ffmpeg`, about a second per variation, written to `qa/videos/` and not committed. |
| Books | Every pipeline has `book/$pipeline.md`, created with the pipeline and updated in the same change as what it describes. Its numbers come from runs. Approval is asked for only once the book is current. |
| Fracture | LOD1 is the baseline for a break. The fracture is its own item, approved apart from the final asset, which stays immutable. |
| Reference material | `reference/$topic/$subject/` holds only public-domain or CC0 photos, as 800-pixel copies, each with a provenance sidecar. They are viewable but never approved. |
| Native match | Systems draw random numbers one per statement and use `foundry::det` math, since GCC and Clang order function arguments differently. |

## Status from the agent

### The tree pipeline (`book/tree_v1.md`)

- **Interface:**
  - **Parameters:** `species` (28 entries from `config/tree_v1_genomes`), `age` (4), `season` (4), `seed` (1 to 1000), `detail` (3), `wind_speed`, `wind_heading`, `gust_damping`, `time`, `break_heading`.
  - **Event:** `break_time`.
  - **Distinct trees:** 28 × 4 × 4 × 1000 × 3 = 1,344,000.
- **Systems:**
  - `tree_rig` grows the skeleton and the break pieces, using Weber and Penn style branching with excurrent and decurrent crowns, whorls, and crown envelopes.
  - `tree_mesh` wraps it in bark and foliage, with five foliage kinds: clumps, needles, rosettes, fronds, and strands.
  - `tree_colorize` paints the seasons: blossom, fruit, fall colour, and snow.
  - `tree_animate` sways the tree as a closed-form damped oscillator, or topples it and throws its limbs.
- **Species:** acacia, apple, baobab, birch, bristlecone pine, cedar of Lebanon, cherry, coconut, coast redwood, dragonwood, American elm, ebony, hickory, Italian cypress, jacaranda, larch, lignum vitae, mahogany, mango, mesquite, oak, olive, osage, pine, sugar maple, spruce, teak, and weeping willow. Wood densities and stiffness come from the USDA *Wood Handbook*. Cypress, cedar, and jacaranda are not listed in it, so their values are estimates.
- **Retuned after comparing with the photos:**
  - **Pine:** it had been a dense, broadleaf-looking blob. It now has a high crown of needle pads on a long, bare orange trunk.
  - **Acacia:** it is now an umbrella on a bare trunk.
  - **Birch:** airier, with its white limbs showing.
  - **Cherry:** it now spreads.
  - **Mesquite:** it no longer sprawls along the ground.
  - **Spruce:** reworked earlier in the day.
- **Native match:** after the last changes, `pipeline_set verify_native` matched in 88 of 88 runs: 11 species × 4 seasons × young and ancient.

### Performance (native, Ryzen AI Max+ 395 with a Radeon 8060S, Vulkan; `demo/perf/`)

| | Native | WebAssembly (foundry) |
|---|---|---|
| Growing a tree (rig + mesh + colorize) | about 0.6 ms; 2.4 ms from spawn to drawable (p50) | about 70 ms |
| Posing a tree (`animate`) | about 7 µs | about 15 ms, almost all instance setup |
| Triangles | 3,600 (p50) to 23,500 (max) at high detail | |

- **Forest:** 3,200 trees run at 4.1 ms p95, sharing 10 meshes with a 99.7% cache hit rate. By CPU frame time, about 16,000 trees fit a 60 fps frame. Measured on its own, the GPU frame goes over 16.7 ms above about 12,800 trees.
- **Bulk breaks:** felling 100 trees in one frame raises the frame time from 0.4 to 0.6 ms. The trees settle in 3 s, and memory comes back to within 0.1 MB.
- **Soak:** memory returns to the same level after every drain.
- **Native against WebAssembly:** 100 of 100 sampled trees and poses match byte for byte in every stress run.
- **QA video:** with 22 species, 1,056 variations exported in 145 s. With 28 species there are now 1,344 variations.

## Known gaps

- **Photos:**
  - I found no free whole-tree photo of ebony (it has leaves only) or hickory (bark only).
  - The bristlecone photo is a cultivated *Pinus aristata*, not the gnarled Great Basin tree the genome models.
  - The second elm photo is a European white elm.
- **Pine crown height:** `crown_ratio` doesn't depend on age, so young pines also carry a high crown.
- **Tree pipeline limits:**
  - The runtime doesn't yet choose `detail` from distance, or cap distinct seeds by quality.
  - Limbs that fly off in a break can end partly in the ground.
  - Mesquite's several stems are approximated by limbs that leave the trunk low.
- **Probe:** it can't see conditional dependencies. `break_heading` only matters once a tree breaks.
- **`PLAN.md`:** "Not in this milestone" still lists "trees and other nature", although trees were delivered today.

## Suggested next steps

The current milestone, "a complex system", has two TODOs, and today's work feeds both:
- **Rocks that break uniquely.** These can build on fracture: a rock pipeline whose break is generated per instance rather than baked once per asset. It would reuse the cut and the rigid-body bake as transforms, or move them into a system.
